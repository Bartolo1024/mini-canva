# Reward experiments and design decisions

Runtime uses the [unweighted additive equation](REWARD_EQUATIONS.md). This note preserves
why that choice was made and distinguishes experimental evaluators from deployed scoring.
The examples are constructed counterexamples, not statistical accuracy or trained-policy results.

## Applied simplifications

Task-specific weights were removed: the old Summer Sale priorities 2/1/2/1/3 were authored
heuristics, not learned or calibrated values. T is now an arithmetic mean. Outer mixture
settings were also removed; T and Q enter symmetrically. Exact duplicate requirements are
rejected to prevent straightforward reweighting by repetition.

Size relations now use literal comparisons: 110 is larger than 100 and receives full
comparison credit, without an inferred preferred size ratio. All retained scoring heuristics
are explicit global YAML settings; their values are conventions, not empirical optima.
No size floor or clutter penalty was added to runtime. Old `weight`, `alpha`, and `beta`
fields are rejected rather than silently ignored.

## Addition versus multiplication

The current comparison uses the same unweighted T, Q, and gate for all three formulas:

| Formula | Range | Consequence |
| --- | --- | --- |
| `G(T+Q)−1` | [−1,1] | Keeps task-repair signal even when Q=0 |
| `GTQ−1` | [−1,0] | Perfect designs receive 0; a zero factor hides improvements |
| `2GTQ−1` | [−1,1] | Stronger compensation control, but the same zero-factor plateau |

Selected measurements regenerated by `python -m tests.reward_support.product_check`:

| Raw scenario | Current additive | Literal product | Normalized product |
| --- | ---: | ---: | ---: |
| valid_summer | +1.000 | +0.000 | +1.000 |
| wrong_cta_color | +0.800 | −0.200 | +0.600 |
| bad_contrast | +0.378 | −0.550 | −0.099 |
| readable_role_spam | +1.000 | +0.000 | +1.000 |
| tiny_image | +1.000 | +0.000 | +1.000 |
| ink_background | +1.000 | +0.000 | +1.000 |
| repair_color_bad | −0.200 | −1.000 | −1.000 |
| repair_color_good | +0.000 | −1.000 | −1.000 |

Addition passes 15 of 21 constructed behavioral checks; both products pass 14. All fail
to distinguish clean designs from six full-score attacks. Products additionally miss the
CTA-color repair while an unrelated collision keeps Q=0. These counts justify a local
trade-off, not a general accuracy claim. No recombination can distinguish scenes with
identical T and Q.

## Offline measurement-repair prototype

[`proposals.py`](../tests/reward_support/proposals.py) also compares additive, product, and
minimum aggregation after experimental changes to the measurements:

- Normalized size attenuation prevents tiny nontext elements receiving full presence.
- A representative bound to each explicit primary requirement supplies its dependent properties.
- Contrast samples topmost background patches beneath visible ink rectangles.
- Capped duplicate/extra-object costs discourage disjoint spam while allowing decoration.

An earlier weighted-reward study found these changes separated tiny images, invisible ink,
and spam from clean references; changing aggregation alone did not. Its old numeric tables
are superseded because current utilities evaluate the unweighted runtime. The prototype
remains outside the environment and MCP reward pipeline. Its thresholds are experimental,
not recommended per-prompt tuning or deployed safeguards.

Its limitations include rectangular ink, greedy rather than global matching, sliver-sensitive
background sampling, capped penalty saturation, and no missing-dependency N/A handling.
Product/minimum variants also lose repair signal when Q=0. Retaining the simpler runtime
was an explicit choice; the [known loopholes](REWARD_HACKING.md) remain visible.

## Reproduce

```sh
uv run --locked python -m tests.reward_support.product_check
uv run --locked python -m tests.reward_support.proposals
uv run --locked pytest -q tests/test_reward_proposals.py
```

Both utilities support `--json` for complete computed reports. They are analysis tools;
running them does not replace the production reward or its configuration.
